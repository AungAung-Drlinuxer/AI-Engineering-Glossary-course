အတိုင်းအတာ သို့မဟုတ် အသုံးဝင်ပုံ ဆိုတဲ့ ၃ ကြောင်းဖြင့် ရေးထားသည်။ term ၁၇ ခုကို အဆင့် ၄ ခုအဖြစ် စီထားသည်။

## ၁။ တိုင်းတာမှု၏ ရည်မှန်းချက် နှင့် ယုံထိုက်မှု

### Alignment

Alignment ဆိုတာ model ဒါမှမဟုတ် စနစ်တစ်ခုက ရည်ရွယ်ထားတဲ့ ပန်းတိုင်၊ ကန့်သတ်ချက်နဲ့ လူသား ဦးစားပေးချက်တွေနဲ့ ကိုက်ညီအောင် ပြုမူစေဖို့ လုပ်တဲ့ လုပ်ငန်းစဉ်ကို ဆိုလိုပါတယ်။
ဥပမာ မေးခွန်း ၁၀၀ ကို စမ်းတဲ့အခါ ၉၀ က ရည်ရွယ်ချက်နဲ့ ကိုက်ညီအောင် ဖြေပေမယ့် ကျန် ၁၀ က ကန့်သတ်ချက်ကို ကျော်လွန်ရင် ကိုက်ညီမှု ၀.၉၀ ဖြစ်ပါတယ်။
ကိုက်ညီမှု ၀.၉၀ က ကောင်းတယ်လို့ ထင်ရပေမယ့် adversarial အခြေအနေမှာ ကျော်လွန်တဲ့ ၁၀ ခုက အန္တရာယ် ဖြစ်စေနိုင်ပါတယ်။

### Benchmark Contamination

Benchmark Contamination ဆိုတာ evaluation အတွက် သုံးတဲ့ နမူနာတွေနဲ့ တိုင်းတာခံ စနစ်ကို pretrain၊ tune၊ prompt လုပ်ရာမှာ သုံးခဲ့တဲ့ data အကြား ထပ်နေမှု ဒါမှမဟုတ် အချက်အလက် ယိုစိမ့်မှုကို ဆိုလိုပါတယ်။
ဥပမာ benchmark မေးခွန်း ၅၀၀ ထဲက ၁၀၀ ဟာ training data ထဲ ပါခဲ့ရင် ထပ်နေမှုနှုန်း ၀.၂၀ ဖြစ်ပါတယ်။
ထပ်နေမှု ၁၀၀ ခု ရှိရင် score က မမြင်ဖူးတဲ့ အလုပ်ကို ဖြေနိုင်စွမ်းထက် ယခင် ကြုံဖူးမှုကို ပြသနိုင်ပါတယ်။

### Calibration

Calibration ဆိုတာ စနစ်က ဖော်ပြတဲ့ ယုံကြည်မှုအဆင့်နဲ့ အဲဒီ အဆင့်ရှိ ခန့်မှန်းချက်တွေ အမှန်ဖြစ်တဲ့ လက်တွေ့ အကြိမ်အရေအတွက် အကြား ကိုက်ညီမှုကို ဆိုလိုပါတယ်။
ဥပမာ confidence ၀.၉၀ ပေးတဲ့ ခန့်မှန်းချက် ၂၀၀ အနက် ၁၅၀ သာ အမှန်ဖြစ်ရင် လက်တွေ့ တိကျမှုက ၀.၇၅ ဖြစ်ပြီး ကွာဟမှု ၀.၁၅ ရှိပါတယ်။
ကွာဟမှု ၀.၁၅ လောက် ရှိရင် confidence ၀.၉၀ ကို ယုံလို့ မရပါဘူး — recalibrate လုပ်ရပါတယ်။

### Distribution Shift

Distribution Shift ဆိုတာ စနစ်ကို တည်ဆောက်ရန် ဒါမှမဟုတ် evaluate လုပ်ရန် သုံးတဲ့ data distribution နဲ့ deploy ပြီးနောက် ကြုံတွေ့ရတဲ့ distribution အကြား ကွာခြားမှုကို ဆိုလိုပါတယ်။
ဥပမာ မူလ slice မှာ တိကျမှု ၀.၉၀ ရပေမယ့် deploy ပြီးနောက် နမူနာ ၂၀၀ ရှိတဲ့ slice အသစ်မှာ ၀.၇၀ သာ ရရင် ကျဆင်းမှု ၀.၂၀ ဖြစ်ပါတယ်။
ကွာဟမှု ၀.၂၀ ဆိုရင် held-out test အောင်ခဲ့တာက ထုတ်လုပ်မှု စွမ်းဆောင်ရည်ကို မဖော်ပြတော့ပါဘူး။

## ၂။ စမ်းသပ် အစု တည်ဆောက်ပြီး အဖြေတစ်ခုကို score ခြင်း

### Eval Set

Eval Set ဆိုတာ သတ်မှတ်ထားတဲ့ စွမ်းရည် ဒါမှမဟုတ် အန္တရာယ်တစ်ခုအတွက် AI စနစ်ကို တိုင်းတာရန် input၊ မျှော်လင့်ချက်၊ scoring rule နဲ့ metadata စုစည်းထားတဲ့ version စီမံထားတဲ့ အစုကို ဆိုလိုပါတယ်။
ဥပမာ မေးခွန်း ၂၀၀ ပါတဲ့ eval set မှာ ၁၅၀ မှန်ရင် တိကျမှု ၀.၇၅ ဖြစ်ပါတယ်။
ထပ်ခါတလဲလဲ သုံးလို့ ရတဲ့ အစုတစ်ခု ရှိမှ မရေရာတဲ့ အရည်အသွေး အဆိုတွေကို နှိုင်းယှဉ်နိုင်တဲ့ အထောက်အထား ဖြစ်လာပါတယ်။

### Evaluation (Eval)

Evaluation (Eval) ဆိုတာ ရှင်းလင်းတဲ့ အောင်မြင်မှု စံနှုန်း၊ data၊ scorer နဲ့ ပြန်လည်စစ်ဆေးတဲ့ လုပ်ထုံးလုပ်နည်းတွေ သုံးပြီး ကိုယ်စားပြုတဲ့ အလုပ်တွေမှာ စနစ်ရဲ့ အပြုအမူကို တိုင်းတာတဲ့ လုပ်ငန်းစဉ်ကို ဆိုလိုပါတယ်။
ဥပမာ retrieval မပြောင်းခင် ၀.၇၂ ရခဲ့တဲ့ eval set ကို ပြောင်းပြီးနောက် ပြန် run ရင် ၀.၈၁ ရပြီး တိုးတက်မှု ၀.၀၉ ဖြစ်ပါတယ်။
ဒီလို နှိုင်းယှဉ်နိုင်တဲ့ လုပ်ငန်းစဉ် မရှိရင် demo အနည်းငယ်ရဲ့ ခံစားချက်နဲ့သာ အရည်အသွေး ဆုံးဖြတ်ရပါတယ်။

### Exact Match (EM)

Exact Match (EM) ဆိုတာ output ကို ပုံမှန်ပြုလုပ်ပြီးနောက် လက်ခံထားတဲ့ အကိုးအကား အဖြေနဲ့ အတိအကျ တူညီမှသာ မှန်တယ်လို့ ရေတွက်တဲ့ metric ကို ဆိုလိုပါတယ်။
ဥပမာ အဖြေ ၁၀၀ အနက် ၆၀ က အတိအကျ ကိုက်ညီရင် EM score ၀.၆၀ ဖြစ်ပါတယ်။
ကျန် ၄၀ ထဲက တချို့က format ကွာရုံသာ ဖြစ်နိုင်တာမို့ EM တစ်ခုတည်းနဲ့ အရည်အသွေး ဆုံးဖြတ်လို့ မရပါဘူး။

## ၃။ အရည်အသွေး၊ ဘေးကင်းရေး နှင့် အကဲဖြတ်သူ model

### Guardrails

Guardrails ဆိုတာ input၊ tool အသုံးပြုမှု၊ output၊ permission နဲ့ escalation တွေကို ကန့်သတ်တဲ့ စနစ် ထိန်းချုပ်မှုတွေကို ဆိုလိုပါတယ်။
ဥပမာ တိုက်ခိုက်မှု ၅၀ ကို စမ်းတဲ့အခါ အလွှာ ၁ ခုတည်းက ၃၀ ကို ဖမ်းနိုင်ပေမယ့် အလွှာ ၃ ခု စုစုပေါင်း ၄၅ ကို ဖမ်းနိုင်ပါတယ်။
ဖမ်းနိုင်မှုက ၀.၆၀ ကနေ ၀.၉၀ အထိ တက်လာတာမို့ ထိန်းချုပ်မှုကို အန္တရာယ်အလိုက် အလွှာလိုက် စီစဉ်ရပါတယ်။

### Hallucination

Hallucination ဆိုတာ မှားယွင်းတဲ့၊ ရနိုင်တဲ့ အထောက်အထားနဲ့ ပံ့ပိုးမှု မရှိတဲ့ ဒါမှမဟုတ် အလုပ်ရဲ့ အမှန်တရား အရင်းအမြစ်နဲ့ မကိုက်ညီတဲ့ ဖန်တီးထုတ်လုပ်ထားတဲ့ အကြောင်းအရာကို ဆိုလိုပါတယ်။
ဥပမာ citation ၅၀ ကို စစ်တဲ့အခါ ၄၀ သာ အဆိုကို အမှန်တကယ် ပံ့ပိုးရင် ပံ့ပိုးမှုနှုန်း ၀.၈၀ ဖြစ်ပါတယ်။
ကျန် ၁၀ ခုက ဖြေချောနေပေမယ့် ပံ့ပိုးမှု မရှိတာမို့ output ချောတာနဲ့ အမှန်ဖြစ်တာ မတူပါဘူး။

### Least Privilege

Least Privilege ဆိုတာ model၊ agent၊ tool ဒါမှမဟုတ် အသုံးပြုသူကို လက်ရှိ အလုပ်အတွက် လိုအပ်တဲ့ permission ကိုသာ၊ လိုအပ်တဲ့ ကာလအတွက်သာ ပေးတာကို ဆိုလိုပါတယ်။
ဥပမာ documentation agent ကို source file ၂၀ အတွက် read ပေးပြီး branch ၁ ခုအတွက်သာ write ပေးရင် ထိခိုက်နိုင်တဲ့ လမ်းကြောင်း ၂၀ ကနေ ၁ ခုကို ကျသွားပါတယ်။
ခွင့်ပြုချက် ကျဉ်းလိုက်တာက ကျရှုံးမှု တစ်ခုရဲ့ ထိခိုက်မှုကို ၂၀ ဆ လျှော့ချပေးပါတယ်။

### LLM-as-a-Judge

LLM-as-a-Judge ဆိုတာ ဘာသာစကား model တစ်ခုကို သုံးပြီး အခြား စနစ်ရဲ့ output ကို rubric တစ်ခုနဲ့ ဆန့်ကျင်စွာ score၊ နှိုင်းယှဉ်၊ အမျိုးအစားခွဲ ဒါမှမဟုတ် ဝေဖန်တာကို ဆိုလိုပါတယ်။
ဥပမာ judge model က အဖြေ ၂၀၀ ကို score ပြီး လူသား label နဲ့ ၁၆၀ ကိုက်ညီရင် ကိုက်ညီမှု ၀.၈၀ ဖြစ်ပါတယ်။
ကိုက်ညီမှု ၀.၈၀ က လုံလောက်တယ်လို့ မဆိုနိုင်တာမို့ judge score ကို ground truth အဖြစ် သုံးလို့ မရပါဘူး။

### Model Card

Model Card ဆိုတာ model တစ်ခုရဲ့ ရည်ရွယ်ထားတဲ့ အသုံးပြုမှု၊ evaluation အခြေအနေ၊ စွမ်းဆောင်ရည် လက္ခဏာ၊ ကန့်သတ်ချက်နဲ့ သက်ဆိုင်တဲ့ ဘေးကင်းရေး စဉ်းစားချက်တွေကို ဖော်ပြတဲ့ အစီရင်ခံစာကို ဆိုလိုပါတယ်။
ဥပမာ model version ၁ ခုအတွက် အုပ်စုခွဲ ၅ ခုရဲ့ ရလဒ်၊ တားမြစ်ထားတဲ့ အသုံးပြုမှုနဲ့ သိရှိထားတဲ့ ကျရှုံးမှု ပုံစံတွေကို ရေးထားရပါတယ်။
ဤအချက်အလက်တွေက အောက်ပိုင်း တည်ဆောက်သူက အထောက်အထား သက်ဆိုင်မှု ရှိ မရှိ ဆုံးဖြတ်နိုင်အောင် ကူညီပါတယ်။

### Pass@k

Pass@k ဆိုတာ အလုပ်အစုတစ်ခုမှာ k ကြိမ် နမူနာယူထားတဲ့ လျာထားချက်တွေထဲက အနည်းဆုံး တစ်ခု စစ်ဆေးမှု အောင်တဲ့ အလုပ်တွေရဲ့ အချိုးအစားကို ဆိုလိုပါတယ်။
ဥပမာ အလုပ် ၁၀၀ အတွက် k=10 နမူနာယူပြီး ၆၀ ခုမှာ အနည်းဆုံး တစ်ခု အောင်ရင် pass@10 က ၀.၆၀ ဖြစ်ပါတယ်။
ဒါက တစ်ကြိမ်တည်း တိကျမှု မဟုတ်ဘဲ နမူနာ ယူနိုင်တဲ့ အကြိမ်အရေအတွက်ရဲ့ တန်ဖိုးကို တိုင်းတာပါတယ်။

## ၄။ ဖမ်းယူနိုင်မှု၊ တိုက်ခိုက်မှု နှင့် လွှတ်ရန် ဂိတ်

### Precision & Recall

Precision & Recall ဆိုတာ အမှတ်အသားပြုထားတဲ့ အရာတွေထဲ မည်မျှ မှန်တာကို Precision က မေးပြီး သက်ဆိုင်တဲ့ အရာတွေထဲ မည်မျှ ရှာတွေ့တာကို Recall က မေးတဲ့ metric နှစ်ခုကို ဆိုလိုပါတယ်။
ဥပမာ precision ၀.၈၀ နဲ့ recall ၀.၅၀ ရရင် F1 က ၀.၆၁၅ ဖြစ်ပါတယ်။
Metric နှစ်ခုက ဆန့်ကျင်ဘက် ဦးတည်ချက် ရှိတာမို့ ကုန်ကျစရိတ် အကြီးဆုံး အမှားအလိုက် ဦးစားပေးရမည့် metric ကို ရှင်းလင်းစွာ သတ်မှတ်ရပါတယ်။

### Prompt Injection

Prompt Injection ဆိုတာ ယုံကြည်လို့ မရတဲ့ အကြောင်းအရာက model ကို ရည်ရွယ်ထားတဲ့ ညွှန်ကြားချက် လျစ်လျူရှုစေခြင်း၊ data ဖော်ထုတ်စေခြင်း ဒါမှမဟုတ် tool အလွဲသုံးစေခြင်းဖြင့် လွှမ်းမိုးတဲ့ တိုက်ခိုက်မှုကို ဆိုလိုပါတယ်။
ဥပမာ red-team စမ်းသပ်မှု ၅၀ အနက် ၈ ခု အောင်ရင် အောင်မြင်မှုနှုန်း ၀.၁၆ ဖြစ်ပါတယ်။
အောင်မြင်မှု ၀.၁၆ ရှိတာက system prompt ခိုင်မာရုံနဲ့ မလုံလောက်ကြောင်း ပြသတာမို့ ပြင်ပ အကြောင်းအရာကို ယုံကြည်လို့ မရတဲ့ အရာအဖြစ် သတ်မှတ်ရပါတယ်။

### ROUGE

ROUGE ဆိုတာ n-gram ထပ်တူမှု ဒါမှမဟုတ် longest common subsequence သုံးပြီး ဖန်တီးထားတဲ့ စာသားကို အကိုးအကား စာသားနဲ့ နှိုင်းယှဉ်တဲ့ metric အုပ်စုကို ဆိုလိုပါတယ်။
ဥပမာ အကိုးအကား စကားလုံး ၄၀ ထဲက ၂၄ လုံး ထပ်ပြီး ဖန်တီးထားတဲ့ စကားလုံး ၃၀ ရှိရင် ROUGE F1 က ၀.၆၈၆ ဖြစ်ပါတယ်။
F1 ၀.၆၈၆ ရတာက စကားလုံး ကူးချထားခြင်းကို ဆုချနိုင်ပြီး အချက်အလက် မှန်ကန်မှုကို သက်သေမပြပါဘူး။

### Verification Gate

Verification Gate ဆိုတာ သတ်မှတ်ထားတဲ့ အထောက်အထားက မှန်ကန်မှု ဒါမှမဟုတ် အရည်အသွေး စံနှုန်းတစ်ခုကို ဖြည့်ဆည်းတဲ့အထိ တိုးတက်မှုကို တားဆီးတဲ့ ထိန်းချုပ်မှု အမှတ်ကို ဆိုလိုပါတယ်။
ဥပမာ coding အလုပ်တစ်ခုမှာ check ၄ ခု (patch သက်ရောက်မှု၊ test အောင်မှု၊ တားမြစ်ထားတဲ့ file မပြောင်းလဲမှု၊ artifact တည်ရှိမှု) ရှိရင် ၄ ခုလုံး အောင်မှ ပြီးစီးခွင့် ပြုပါတယ်။
၄ ခုအနက် ၁ ခု ကျရင် gate က ပိတ်ထားတာမို့ model ပြီးပြီ ဆိုတဲ့ အဆိုကို အထောက်အထားနဲ့ စစ်ပါတယ်။
