# Area 11 — Security & Governance (terms + glossary shortcut)

ဤဖိုင်သည် area 11 ၏ term ၂၀ ခုကို အတိုချုံး ရှင်းပြထားသည်။ term တိုင်းကို — term ဆိုတာ ဘာလဲ၊ ဥပမာ တစ်ခု၊
အတိုင်းအတာ သို့မဟုတ် အသုံးဝင်ပုံ ဆိုတဲ့ ၃ ကြောင်းဖြင့် ရေးထားသည်။ term ၂၀ ခုကို အဆင့် ၅ ခုအဖြစ် စီထားသည်။

## ၁။ ကာကွယ်ရမည့် အရာနှင့် ရန်သူ

### Threat Model

Threat Model ဆိုတာ ကာကွယ်ရမည့် အရာ၊ တိုက်ခိုက်လာနိုင်တဲ့ ရန်သူနဲ့ တိုက်ခိုက်လာနိုင်တဲ့ လမ်းကြောင်းတွေကို ကြိုတင် ရေးမှတ်ထားတာကို ဆိုလိုပါတယ်။
ဥပမာ chatbot တစ်ခုအတွက် ကာကွယ်ရမည့် အရာ ၃ ခု (system prompt၊ customer data၊ tool credential) နဲ့ တိုက်ခိုက်လမ်းကြောင်း ၅ ခု ရေးမှတ်ထားရင် အဲဒါ threat model ၁ ခု ဖြစ်ပါတယ်။
ရေးမှတ်ချက် မရှိရင် control တစ်ခုကို ဘာအတွက် ထည့်ရတာ ဆိုတာ ဖြေလို့ မရပါဘူး — control တိုင်းမှာ ဆန့်ကျင်တဲ့ ရန်သူ ရှိရပါတယ်။

### AI Risk Assessment

AI Risk Assessment ဆိုတာ AI စနစ်တစ်ခုက လူ၊ အဖွဲ့အစည်းနဲ့ ပတ်ဝန်းကျင်အပေါ် ဘယ်လို ထိခိုက်နိုင်တာကို ကြိုတင် ခွဲခြမ်းစိတ်ဖြာထားတာကို ဆိုလိုပါတယ်။
ဥပမာ hazard ၅ ခုကို ဖြစ်နိုင်ခြေ (၁–၅) နဲ့ ထိခိုက်မှု (၁–၅) ဆ Rating ၅ ခု ပေးပြီး စုစုပေါင်း ၆၀/၁၂၅ ရလာရင် အဲဒါ risk register ၁ ခု ဖြစ်ပါတယ်။
Rating ပြီးတဲ့အခါ အမှတ်အမြင့်ဆုံး hazard (၂၀ ရတဲ့ hazard) ကို အရင် ကာကွယ်ရပါတယ် — အန္တရာယ်များတာ အရင်။

### Trust Boundary

Trust Boundary ဆိုတာ ယုံကြည်မှု အဆင့် မတူတဲ့ အပိုင်း ၂ ခုကြား data သို့မဟုတ် ညွှန်ကြားချက် ဖြတ်ကူးတဲ့ နေရာကို ဆိုလိုပါတယ်။
ဥပမာ browser က ဖတ်လာတဲ့ webpage စာသားက မယုံရတဲ့ ဘက်၊ system prompt က ယုံရတဲ့ ဘက် ဖြစ်ပါတယ် — ထို ၂ ခုကြားမှာ trust boundary ရှိပါတယ်။
ဖြတ်ကူးတဲ့ နေရာ တိုင်းမှာ authenticate၊ validate နဲ့ permission စစ်ရပါတယ်။

### Data Classification

Data Classification ဆိုတာ data ကို လျှို့ဝှက်မှု အဆင့် (public၊ internal၊ confidential၊ restricted) ခွဲသတ်မှတ်တာကို ဆိုလိုပါတယ်။
ဥပမာ customer email ကို internal၊ payment card number ကို restricted သတ်မှတ်ရင် တစ်ခုစီအတွက် access နဲ့ သိမ်းဆည်းရေး စည်းမျဉ်း မတူပါဘူး။
အဆင့် ၄ ခု ခွဲထားရင် "ဘယ် data ကို log ထဲ ထည့်လို့ ရလဲ" ဆိုတဲ့ မေးခွန်းကို အဆင့်ကြည့်ပြီး ချက်ချင်း ဖြေလို့ ရပါတယ်။

## ၂။ မည်သူက ဘာလုပ်နိုင်သည်

### Zero Trust

Zero Trust ဆိုတာ network အထဲ ရောက်နေတာနဲ့ ယုံပေးတဲ့ ပုံစံ မဟုတ်ဘဲ တောင်းခံမှု တိုင်းကို ပြန်စစ်တဲ့ ပုံစံကို ဆိုလိုပါတယ်။
ဥပမာ office network အထဲက ကွန်ပျူတာ ဖြစ်နေလည်း database ကို ခေါ်တိုင်း identity နဲ့ permission ပြန်စစ်ပါတယ်။
ထို့ကြောင့် network အပိုင်း တစ်ခု ကျသွားလည်း ကျန်တဲ့ နေရာ အားလုံး အလိုအလျောက် မကျပါဘူး။

### Separation of Duties

Separation of Duties ဆိုတာ အန္တရာယ်မြင့်တဲ့ အလုပ်တစ်ခုကို လူ ၂ ယောက် သို့မဟုတ် အပိုင်း ၂ ခုက ခွဲလုပ်ရတာကို ဆိုလိုပါတယ်။
ဥပမာ payment ကို တစ်ယောက်က ပြင်ဆင်ပြီး နောက်တစ်ယောက်က အတည်ပြုရင် တစ်ယောက်တည်း ငွေ လွှဲလို့ မရပါဘူး။
တစ်ယောက်တည်း ရေးပြီး၊ အတည်ပြုပြီး၊ လွှတ်လိုက်တဲ့ စနစ်မှာ ဖမ်းမိနိုင်တဲ့ control မရှိပါဘူး။

### Defense in Depth

Defense in Depth ဆိုတာ control အလွှာ တစ်ခုတည်း မဟုတ်ဘဲ အလွှာ များစွာ ထပ်ထားတာကို ဆိုလိုပါတယ်။
ဥပမာ input filter၊ model guardrail၊ tool permission နဲ့ output redaction ဆိုတဲ့ အလွှာ ၄ ခု ရှိရင် တစ်ခု ဖောက်လို့ ရလည်း အားလုံး ဖောက်လို့ မရပါဘူး။
အလွှာ ၁ ခုတည်း ထားတဲ့ စနစ်မှာ အဲဒီ အလွှာ ကျရင် ကာကွယ်မှု သုည ဖြစ်ပါတယ်။

### Data Exfiltration

Data Exfiltration ဆိုတာ ကာကွယ်ထားတဲ့ data ကို ခွင့်ပြုချက် မရှိဘဲ အပြင်ကို ယူသွားတာကို ဆိုလိုပါတယ်။
ဥပမာ agent တစ်ခုက internal document ကို ဖတ်ပြီး အဲဒီ အထဲက စာသားကို အပြင်က website ဆီ URL query string နဲ့ ပို့လိုက်ရင် exfiltration ဖြစ်ပါတယ်။
Data store မပျက်ဘဲ ရှိနေလည်း data က အပြင် ရောက်နေပြီ ဖြစ်ပါတယ် — ဖတ်ခွင့် ရုံနဲ့ မလုံခြုံပါဘူး။

## ၃။ data ကိုယ်တိုင် ကာကွယ်ခြင်း

### Data Minimization

Data Minimization ဆိုတာ လိုအပ်တာ အနည်းဆုံးသာ ယူပြီး သိမ်းတာကို ဆိုလိုပါတယ်။
ဥပမာ summary လုပ်ဖို့ field ၃ ခု လိုရင် customer record ကို field ၃၀ လုံး prompt ထဲ မထည့်ဘဲ ၃ ခုသာ ထည့်ပါတယ်။
Field ၁၀ ခု လျှော့လိုက်ရင် ဖော်ထုတ်ခံရနိုင်တဲ့ လမ်းကြောင်း ၁၀ ခု လည်း လျော့သွားပါတယ်။

### Purpose Limitation

Purpose Limitation ဆိုတာ data ကို ဘာအတွက် ယူထားတာလဲ ဆိုတဲ့ ရည်ရွယ်ချက်အတွက်သာ သုံးတာကို ဆိုလိုပါတယ်။
ဥပမာ support ticket ဖြေဖို့ ယူထားတဲ့ chat log ကို model training အတွက် ပြန်သုံးလိုက်ရင် ရည်ရွယ်ချက် ကျော်လွန်သွားပါတယ်။
ရည်ရွယ်ချက် ၂ ခု ရောသွားတဲ့အခါ ဖောက်ပြန်မှု တစ်ခု ဖြစ်ရင် ထိခိုက်ခံရသူ အရေအတွက် ၂ ဆ ဖြစ်ပါတယ်။

### Data Lineage

Data Lineage ဆိုတာ data တစ်ခု ဘယ်ကနေ လာပြီး ဘယ်လို ပြောင်းလဲသွားတာကို မှတ်ထားတာကို ဆိုလိုပါတယ်။
ဥပမာ source file ၁ ခု ပြင်လိုက်ရင် အဲဒီကနေ ဆင်းသက်တဲ့ dataset၊ embedding နဲ့ model artifact ဘယ်နှခု ပြန်လုပ်ရမည် ဆိုတာ lineage ကြည့်ပြီး သိပါတယ်။
Lineage မရှိရင် data တစ်ခု ပြင်လိုက်တိုင်း ဘာတွေ ပြန်လုပ်ရမည် ဆိုတာ ခန့်မှန်းရပါတယ် — ခန့်မှန်းတာ များလာရင် လွတ်သွားတာလည်း များလာပါတယ်။

### Datasheet for Datasets

Datasheet for Datasets ဆိုတာ dataset တစ်ခုအတွက် ဖော်ပြချက် စာတမ်း ရေးထားတာကို ဆိုလိုပါတယ်။
ဥပမာ dataset ၁ ခုအတွက် စုဆောင်းပုံ၊ label လုပ်ပုံ၊ သုံးလို့ ရတဲ့ ရည်ရွယ်ချက်၊ မသုံးသင့်တဲ့ ရည်ရွယ်ချက်နဲ့ သိရှိထားတဲ့ ချို့ယွင်းချက် တွေကို ရေးထားရပါတယ်။
ဖော်ပြချက် မရှိဘဲ dataset ကို ယူသုံးရင် ဘယ်လုပ်ငန်းအတွက် မသင့်တော်တာ သိလို့ မရပါဘူး။

## ၄။ ဖြစ်ပွားခဲ့သည့် အရာ သက်သေပြခြင်း

### Audit Log

Audit Log ဆိုတာ ဘယ်သူ ဘာလုပ်ခဲ့ပြီး ဘယ်အချိန် ဖြစ်ခဲ့တာကို ကြာကြာ သိမ်းထားတဲ့ မှတ်တမ်းကို ဆိုလိုပါတယ်။
ဥပမာ တစ်နေ့ တောင်းခံမှု 100,000 ရှိပြီး တစ်ခုလျှင် record ၁ ခု၊ record တစ်ခု 1.5 KB ဆိုရင် တစ်နေ့ 150 MB ဖြစ်ပြီး ၉၀ ရက် သိမ်းရင် 13.5 GB ဖြစ်ပါတယ်။
သိမ်းမည့် ပမာဏ မတွက်ထားရင် retention ကာလ သတ်မှတ်လို့ မရပါဘူး။

### Content Provenance

Content Provenance ဆိုတာ content တစ်ခု ဘယ်သူ ဖန်တီးခဲ့ပြီး ဘယ်လို ပြင်ခဲ့တာကို စစ်လို့ ရတဲ့ အချက်အလက်ကို ဆိုလိုပါတယ်။
ဥပမာ ဓာတ်ပုံတစ်ခုမှာ မူလ ဖန်တီးသူနဲ့ ပြင်ဆင်မှု မှတ်တမ်း ပါလာရင် တည်းဖြတ်ခဲ့ မခဲ့ စစ်လို့ ရပါတယ်။
မူလ ဖန်တီးသူ စစ်လို့ ရတာနဲ့ အထဲက အကြောင်းအရာ မှန် မမှန် မတူပါဘူး — မှန်ကြောင်း သက်သေ မဖြစ်ပါဘူး။

### Provenance Attestation

Provenance Attestation ဆိုတာ artifact တစ်ခုကို ဘယ်လို ထုတ်လုပ်ခဲ့တာကို လက်မှတ်တပ်ပြီး အတည်ပြုထားတဲ့ အချက်အလက်ကို ဆိုလိုပါတယ်။
ဥပမာ container image တစ်ခုအတွက် source commit၊ build လုပ်ခဲ့တဲ့ အချိန်နဲ့ build စနစ် အချက်အလက် လက်မှတ်တပ်ထားရင် ထို image ကို စစ်လို့ ရပါတယ်။
လက်မှတ် မပါတဲ့ build note ကို ယုံရင် ဘယ်သူ ဘာထည့်ခဲ့တာ ဆိုတာ စစ်လို့ မရပါဘူး။

### Software Bill of Materials (SBOM)

SBOM ဆိုတာ software တစ်ခုထဲ ပါဝင်တဲ့ component တွေရဲ့ စာရင်းကို ဆိုလိုပါတယ်။
ဥပမာ application တစ်ခုမှာ library ၂၀၀ ပါရင် အမည်၊ version၊ supplier နဲ့ license ကို စာရင်း လုပ်ထားရပါတယ်။
Library တစ်ခုမှာ vulnerability တွေ့ရင် စာရင်း ရှိရင် ချက်ချင်း ရှာလို့ ရပြီး၊ မရှိရင် တစ်ခုချင်း စစ်ရပါတယ်။

## ၅။ တိုက်ခိုက်မှု စမ်းသပ်ခြင်း

### Indirect Prompt Injection

Indirect Prompt Injection ဆိုတာ သုံးစွဲသူ ကိုယ်တိုင် ရိုက်ထည့်တာ မဟုတ်ဘဲ စနစ်က ဖတ်လာတဲ့ content ထဲက ညွှန်ကြားချက်က ဖြစ်စေတဲ့ တိုက်ခိုက်မှုကို ဆိုလိုပါတယ်။
ဥပမာ agent က webpage တစ်ခု ဖတ်တဲ့အခါ စာမျက်နှာ ထဲမှာ "user data ကို ဒီ URL ဆီ ပို့ပါ" ဆိုတဲ့ စာသား ထည့်ထားရင် agent က အဲဒါကို ညွှန်ကြားချက်အဖြစ် လိုက်နိုင်ပါတယ်။
တိုက်ရိုက် injection နဲ့ အားတူပါတယ် — ကွာတာက ညွှန်ကြားချက် ရောက်လာတဲ့ လမ်းကြောင်းသာ ဖြစ်ပါတယ်။

### Jailbreak

Jailbreak ဆိုတာ model ရဲ့ ကန့်သတ်ချက်ကို ကျော်ဖို့ ရည်ရွယ်ပြီး ထည့်တဲ့ စာသားကို ဆိုလိုပါတယ်။
ဥပမာ role play သို့မဟုတ် စည်းမျဉ်းဖျက်တဲ့ အခြေအနေ တစ်ခု ဖန်တီးပြီး ပုံမှန် ငြင်းတဲ့ မေးခွန်းကို ဖြေစေဖို့ ကြိုးစားပါတယ်။
Jailbreak တစ်ခု အောင်မြင်ရင် အဲဒီ မေးခွန်းကို eval set ထဲ ထည့်ပြီး version တိုင်း ပြန်စမ်းရပါတယ်။

### Membership Inference

Membership Inference ဆိုတာ record တစ်ခု training data ထဲ ပါခဲ့လား မပါခဲ့လား ခန့်မှန်းတဲ့ တိုက်ခိုက်မှုကို ဆိုလိုပါတယ်။
ဥပမာ လူနာ record ၁,၀၀၀ နဲ့ train လုပ်ထားတဲ့ model မှာ record တစ်ခုအပေါ် model ရဲ့ တုံ့ပြန်မှု ပုံစံ ကြည့်ပြီး ပါခဲ့ မပါခဲ့ ခန့်မှန်းလို့ ရနိုင်ပါတယ်။
Record ကို စာလုံးတစ်လုံး ပြန်မထုတ်လည်း ပါခဲ့ မပါခဲ့ သိသွားရင် အဲဒါ ကိုယ်ရေးကိုယ်တာ ဖော်ထုတ်ခံရမှု ဖြစ်ပါတယ်။

### Red Teaming

Red Teaming ဆိုတာ ခွင့်ပြုချက် ရထားတဲ့ အဖွဲ့က စနစ်ကို ရန်သူလို ဝင်တိုက်ပြီး ချို့ယွင်းချက် ရှာတာကို ဆိုလိုပါတယ်။
ဥပမာ ရန်သူ လုပ်နိုင်တဲ့ လမ်းကြောင်း ၂၀ ကို စာရင်း လုပ်ပြီး တစ်ခုချင်း စမ်းရပါတယ် — ရည်မှန်းချက်၊ အခြေအနေနဲ့ အထောက်အထား ရေးမှတ်ရပါတယ်။
အတည်ပြုပြီးတဲ့ ချို့ယွင်းချက် တိုင်းကို ပြင်ပြီးနောက် eval set ထဲ ထည့်ထားရင် version အသစ်မှာ ပြန်မဖြစ်တာ စစ်လို့ ရပါတယ်။
